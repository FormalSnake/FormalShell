# FormalShell macOS e2e rig — Implementation Plan (Task 0 for the macbook era)

> **For the macbook Claude Code instance:** this is your FIRST milestone,
> before any M6 work. Execute it via a Workflow per
> `docs/superpowers/workflow-template.md`. Both Linux hosts (g815, e1504g)
> are OFFLINE — the mac must become fully self-sufficient for FormalShell's
> entire verification loop.

**Goal:** Every existing verification mode — `just build`, `just test`,
`just lint`, `dev/smoke-niri.sh` (plain, `--dump`, `--wallpaper`, `--menu`,
`--notify`, `--center`, `--osd`) — runs from the macbook and produces the
same evidence (exit codes, JSON dumps, screenshots readable via the Read
tool on the mac's filesystem). Acceptance = a full green sweep of all of
them, with screenshots visually verified, before M6 starts.

**Architecture:** Two-layer rig:
1. **Build layer** — an aarch64-linux nix builder so `nix build .#formalshell`
   / `nix flake check -L` (the linux checks) work from the mac. Candidates,
   in preference order; the plan's first task is choosing empirically:
   a. Determinate Nix's built-in linux-builder support, if the installed
      Determinate version ships it (the macbook runs Determinate — check
      `determinate-nixd status` / their docs);
   b. nix-darwin's `nix.linux-builder.enable` (needs a change in the owner's
      nix config repo `~/.config/nix` — allowed: rebuild policy in that
      repo's CLAUDE.md permits darwin-rebuild, and the owner pre-approved
      this rig);
   c. ad-hoc `nix run nixpkgs#darwin.linux-builder` kept alive in a herdr pane.
2. **Runtime layer** — a headless QEMU aarch64 NixOS VM (HVF acceleration,
   virtio-gpu for a virtual DRM display, `-display none`) defined IN THIS
   REPO as `nixosConfigurations.testvm` + a `packages.aarch64-linux.testvm`
   (`config.system.build.vm`) run wrapper: auto-login user, niri as the
   session on the virtual DRM (so the existing NESTED-niri smoke scripts run
   unchanged inside it), openssh with a forwarded port (e.g. 2222), a
   9p/virtiofs share or plain `scp` for pulling screenshots back to
   `./artifacts/` on the mac. The VM includes: niri, the flake's formalshell
   package, matugen, imagemagick, dbus, brightnessctl, wireplumber/pipewire
   (audio smoke), a Nerd Font, and the repo checkout (mounted share
   preferred so edits don't need VM rebuilds).

**Driver:** `dev/vm.sh` — `start` (boot VM headless in background, wait for
ssh), `run <cmd>` (ssh into VM, run inside the repo share), `smoke <flags>`
(run the smoke script inside the VM, scp the produced PNG + JSON back to
`./artifacts/`, print local paths), `stop`. `justfile` gains
`vm-build`, `vm-test`, `vm-smoke *FLAGS`, mirroring the local recipes.

**Constraints:**
- All existing plans' constraints hold (CLAUDE.md hard rules; the VM
  replaces "nested session on the g815" as the isolation boundary — inside
  the VM, the existing scripts still do their own HOME/XDG + dbus-run-session
  isolation, which keeps them portable back to Linux hosts).
- No changes to shell/ source in this plan (rig only). Smoke scripts may
  gain VM-awareness flags but must stay bit-compatible with Linux-host use.
- Screenshots must land on the MAC filesystem and be Read-verified in the
  workflow, same standard as before.
- Commit/push per task as always. CI stays linux-x86_64 (GitHub runners) —
  do not couple CI to the VM.
- If the QEMU/virtio-gpu path proves unable to give niri a working DRM
  device after 3 distinct approaches, fall back to running niri inside the
  VM with its winit/nested backend under a minimal headless wayland session
  (cage/labwc under wlroots-headless + WAYLAND_DISPLAY), and record the
  trade-off. Do not silently downgrade to "unit tests only".

**Suggested task split (refine when authoring the workflow):**
1. Build layer online (pick a/b/c above; evidence: `nix build .#packages.aarch64-linux.formalshell` succeeds from the mac).
2. `nixosConfigurations.testvm` + run wrapper boots headless, ssh reachable.
3. niri session alive on virtual DRM inside VM (`niri msg outputs` over ssh).
4. Repo share + `dev/vm.sh` + just recipes; `vm-test`/`vm-build` green.
5. Full smoke sweep green inside VM incl. screenshots pulled to ./artifacts/ and Read; update CLAUDE.md (macbook verification loop section) + README dev-loop docs.

Then proceed to authoring the M6 plan (spec §Surfaces 2/4 + calendar
addendum, DESIGN.md binding) and its workflow.
