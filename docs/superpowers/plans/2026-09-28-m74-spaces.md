## What carries over, what does not

- Kept: each workspace slot showing the icons of its windows, the active
  slot opening wider, the focused window lit and the rest dimmed, urgent
  in `destructive`, click a slot to go there, click an icon to focus that
  window, wheel over the row to step workspaces, icon tooltips carrying the
  window title, persistent slots, agent badges (spinner working, pulsing
  `!` blocked, check done) with the slot itself pulsing while an agent on
  it waits, a `peek` IPC verb.
- Changed: the hover preview. The plugin draws live `ScreencopyView`s,
  which this repo bans outright (CLAUDE.md, `LockSurface.qml`'s header).
  Ours is a schematic: a card hanging off the cell (the shell's own joined
  panel shape) with each window drawn as a box at its `rect` scaled to the
  output, carrying its icon and title, clickable to focus.
- Changed: agent state comes from herdr, not Claude Code hooks. herdr
  already classifies every agent kind it knows (claude, codex, opencode,
  ...), so no hook install and no pid-walk handshake. A Claude session
  outside herdr gets no badge.
- Dropped: the plugin's settings panel and most of its 25 knobs. The shell
  reads settings.json only. Keys kept, under `workspaces.*`: `showApps`
  (`all` | `active` | `hover`, default `hover`: active slot always, others
  while hovered), `maxIcons` (8), `persistent` (5), `agents` (true),
  `preview` (true). Styling (fills, radii, badge colours, motion) is the
  theme's per `specs/2026-09-18-theme-boundary.md`, never a key.
- Kept from our row: the travelling pill as the active-slot indicator
  (M48/M54 D2 motion, now stretching to the active slot's wider box), the
  vertical-bar rotation rules, the maintained `visibleWorkspaces` model.

## herdr facts this leans on (checked 2026-09-28, herdr 0.9.1)

- `herdr agent list` prints `{"result":{"agents":[{agent, agent_status,
  pane_id, workspace_id, terminal_title_stripped, ...}]}}`; statuses are
  `idle | working | blocked | done | unknown`.
- The API has no unscoped status-change event (`pane.agent_status_changed`
  needs a `pane_id`), so the source polls, every 2s, like
  `dualsense-herdr` in the nix config already does.
- A local client is a `herdr` process (optionally `--session <name>`)
  under the terminal's pid. A remote one is `herdr --remote <target>
  [--session <name>]` with a `herdr client` child.
- Over ssh the remote login shell may be fish with a minimal PATH, so the
  remote loop runs under `bash -c` and resolves herdr from
  `command -v herdr`, then `$HOME/.nix-profile/bin/herdr`, then
  `/etc/profiles/per-user/$USER/bin/herdr`.

## Task 1: HerdrService (sonnet)

- `shell/Herdr/model.js`, pure and tested (`tests/tst_herdr_model.qml`):
  - `parseClient(args)`: a process argv string to `null` or
    `{ key, remote, session }` (`herdr`, `herdr --session s`,
    `herdr --remote mac`, `herdr --remote mac --session s`; `herdr client`,
    `herdr server`, `herdr agent ...` and every other subcommand are not
    clients).
  - `clientsByWindow(psRows, windowPids)`: walks a `pid ppid args` table
    down from each window pid and returns `{ <pid>: key }` for the first
    client found in that subtree.
  - `aggregate(agents)`: `blocked` > `working` > `done` > `""` (idle and
    unknown draw nothing).
  - `parseList(line)`: one `agent list` line to the agents array, `null`
    on garbage.
- `shell/Services/HerdrService.qml` singleton: reads a `ps -eo
  pid=,ppid=,args=` table when `CompositorService.windows` changes
  (debounced), keeps one long-lived poll `Process` per distinct client key
  (local: `sh -c` loop over `herdr [--session s] agent list`; remote: `ssh
  -o BatchMode=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=2
  <target> "bash -c '...'"`), stops a poll when no window holds its key,
  restarts a dead one with backoff. Publishes `stateByWindow` (window id to
  `working|blocked|done`) and `stateByKey`. No herdr on PATH or an ssh that
  fails: no badges, nothing faked, one line in `debug dump`.
- `procps` (for `ps`) and `openssh` on the wrapper PATH in
  `nix/package.nix` if not already there; herdr itself is the user's, not
  a runtime dependency.
- Verify: `just vm-test` green including the new file; `just build`.
