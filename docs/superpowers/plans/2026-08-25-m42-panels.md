# M42: every panel on the shadcn primitives, keyboard included

**Date:** 2026-08-25
**Status:** approved, pre-implementation
**Spec:** `docs/superpowers/specs/2026-08-25-shadcn-omarchy-redesign.md`
(spec wins on conflict). `docs/DESIGN.md` is the rulebook.
**Builds on:** M41 (`05447c4`..`df3d2dd`): tokens, Lucide, primitives,
`Panel` chrome with the cursor model, `NetworkPanel` as the worked example,
the Hyprland rig (`just vm-smoke --panel <name>`).

## Why

Sixteen panels still render through D3's compatibility mapping: old Cell
props, `MetaLabel` colons stripped but the ledger layouts intact, dithered
heroes, mono everywhere, no keyboard cursor. M41 proved the primitives on
the network panel; this milestone ports the rest the same way and adds the
one keybind entry point the spec still owes, `panel toggleAt <n>`.

## Scope

In: `AudioPanel`, `BluetoothPanel`, `PowerPanel`, `CalendarPanel`,
`WeatherPanel`, `DisplayPanel`, `MediaPanel` (+ `AnimatedAlbumArt`),
`MonitorPanel`, `AppMenuPanel`, `UsagePanel`, `GithubPanel`,
`SystemUpdatePanel`, `TailscalePanel`, `AirpodsPanel`, `DualsensePanel`;
the bar widgets that open them; `panel toggleAt`; the `--panel` rig leg
for every registered name; `CardTitleBar` removal from `MediaPanel`.

Out: `Center.qml` (M44, the other `CardTitleBar` consumer), launcher
chrome and app views (M43), toasts/OSD (M44), lock/picker (M45), bar
widgets with no panel (`Tray`, `Indicators`, `Chevron`, `Visualizer`,
`KeyboardLayout`, `CommandModule`, `QmlModule`, `PluginBarModule`: M45's
sweep), new features in any panel.

## Locked decisions

### D1: one recipe per panel, NetworkPanel is the reference

Every port follows `shell/Surfaces/Panels/NetworkPanel.qml` as landed in
`05691a6` and `33fdaca`: `panelIcon`, sections as `SectionLabel` plus
`Cell` rows `Theme.space.rowGap` apart, heroes as `PanelHero`, actions as
`Button`/`IconButton`, sliders as `Track` with a `Cell` row around them,
sans for words and mono for values (spec "Type"), `Icon` by name, no raw
glyph left in the file (`rg -l '[\x{E000}-\x{F8FF}\x{F0000}-\x{FFFFF}]'`
must not list it), no `DitherImage`/`DitherFill`, no `Theme.fontFamily`
(use `fontFamilySans`/`fontFamilyMono`), no `MetaLabel` (use
`SectionLabel`), no D3-mapped Cell props (`accent`, `ink`, `standalone`,
`pending`; `selected` only where a row is genuinely the chosen one, e.g.
the active sink). Every service call, IPC route and state the old file
exposes survives; a port that drops a feature to fit the layout is a
failed port.

### D2: keyboard is part of the port, not a follow-up

Each panel sets `cursorCount` to its navigable rows and handles
`cursorActivated(index)`; `cursorSection`/`sectionCount` group rows when a
panel has more than one list (Bluetooth: paired then available). Rows draw
`cursor: index === panel.cursorIndex && panel.cursorActive`. A slider row
under the cursor takes Left/Right as -5/+5 percent through `moveRequested`
with `dx`; a toggle row takes Enter; a row with a destructive action
(forget, disconnect) takes `x` through `deleteRequested`. Panels that
consumed `keyPressed` (PowerPanel's picker, and whichever others
`rg -l 'onKeyPressed' shell/Surfaces/Panels` lists) move onto the cursor
model and stop reading raw keys. Tab cycles sections then the footer
button. The one exception is `AppMenuPanel`, which drives a foreign
window's menu; it keeps whatever key handling it has.

### D3: sizes come from the spec

`popupWidthDefault` unless the spec names the panel under `Wide` (media,
monitor, calendar). Nothing sets a literal width.

### D4: `toggleAt` counts panel-bearing cells of the resolved right region

`panel toggleAt <n>`: take `Bar/layout.js`'s resolved right region in
order, keep the entries whose widget opens a panel (the map lives in one
place, `shell/Bar/panels.js`: widget name to panel name, pure, tested), and
open the nth (1-based) through the registry the same way `panel toggle
<name>` does. Out of range returns the error string `no panel at <n>`.
A collapsed chevron group does not change the count: hidden cells still
count, since the keybind is about the layout the user configured, not what
is currently showing.

## Tasks

One subagent per task, sequential, verification before commit. Every
panel task runs `just vm-smoke --panel <name>` for each panel it ported and
reads the PNG: the rig's honest empty states (`NO ADAPTER`, `NO DEVICES`,
an absent battery) are what they show on the VM, which is fine; the chrome,
the faces and the cursor ring on row 0 after a `panel cursor` nudge are
what to look for. If a panel name is not in `PanelIpc`'s registry, add it
there first (unknown names must still return an error string).

### Task 1: audio, bluetooth, power

Files: `AudioPanel.qml`, `BluetoothPanel.qml`, `PowerPanel.qml`, their
widgets (`AudioWidget`, `MicWidget`, `BluetoothWidget`, `Battery`), tests
that touch them. Audio: sinks/sources as sections, volume as a `Track` row
per device, mute as an `IconButton`. Bluetooth: `PAIRED (n)` /
`AVAILABLE (n)`, connect on Enter, forget on `x`, adapter power as the
header toggle like network's wifi button. Power: profile rows with
`selected` on the active profile, battery hero with the estimate in mono,
the charging pulse kept (spec: the one continuous-motion carve-out).
Commit: `feat(panels): audio, bluetooth and power on the shadcn primitives`.

### Task 2: calendar, weather, display

Files: `CalendarPanel.qml`, `WeatherPanel.qml`, `DisplayPanel.qml`,
`Clock`, `WeatherWidget`, `DisplayWidget`, tests. Calendar is `Wide`: month
grid as `Cell`s with `radiusSm`, today `active`, days with events carrying
a 4px `primary` dot, the day's event rows below with times in mono;
arrows move across days, Enter selects a day. Weather: hero with the
current reading in `display` mono, forecast rows. Display: outputs as
rows, scale/enable/mirror controls as `Button`s, no dither.
Commit: `feat(panels): calendar, weather and display on the shadcn primitives`.

### Task 3: media, monitor, app menu

Files: `MediaPanel.qml`, `AnimatedAlbumArt.qml`, `MonitorPanel.qml`,
`AppMenuPanel.qml`, `NowPlaying`, `MonitorWidget`, `ActiveWindow`, tests.
Media (`Wide`): album art in a `radiusMd` frame (plain, not dithered),
title sans / artist muted, transport as `IconButton`s, progress as
`Track`, PLAYERS as a row of `secondary` chips; drop `CardTitleBar` here
and its `qmldir` entry only if `Center.qml` is its last consumer after
this (it is; leave the file, delete the entry in M44). Monitor: CPU/MEM/GPU
as labelled mono numbers over `Track`s. App menu: rows only.
Commit: `feat(panels): media, monitor and app menu on the shadcn primitives`.

### Task 4: usage, github, system update, tailscale

Files: `UsagePanel.qml`, `GithubPanel.qml`, `SystemUpdatePanel.qml`,
`TailscalePanel.qml`, their widgets, tests. Usage: per-provider rows with
`Track`s and mono figures. Github: notification rows, open on Enter.
System update: status hero, `outline` update button, log rows in mono.
Tailscale: peer rows, connect toggle in the header.
Commit: `feat(panels): usage, github, system update and tailscale on the shadcn primitives`.

### Task 5: airpods, dualsense

Files: `AirpodsPanel.qml`, `DualsensePanel.qml`, `AirpodsWidget`,
`DualsenseWidget`, tests. Battery figures mono, per-bud/controller rows,
`READ ONLY` as a `secondary` chip in `titleActions`.
Commit: `feat(panels): airpods and dualsense on the shadcn primitives`.

### Task 6: `panel toggleAt`

Files: `shell/Bar/panels.js` (new, pure), `shell/Ipc/PanelIpc.qml`,
`shell/Core/PanelRegistry.qml` if the open path needs a name-based hook,
`tests/tst_bar_panels.qml`, `dev/smoke.sh` (`--panel-at <n>` leg: opens
by index, dumps `panel state`, asserts the name matches the resolved
layout's nth panel widget, screenshots), `docs/USAGE.md` (IPC table),
`docs/examples/hyprland/formalshell.conf` (the `SUPER+CTRL+1..9` binds,
the first keybinds to land in that file).
Commit: `feat(panel): open the nth bar panel over ipc`.

### Task 7: rig sweep and docs

Run `just vm-smoke --panel <name>` for every registered name on the
Hyprland rig, read every PNG, fix what is wrong in place (a fix commit per
panel if needed, `fix(panels): ...`). Then `docs/ARCHITECTURE.md`'s two
"Flexoki fallback" tree-diagram lines (`:71`, `:76`), the panel host
section, `docs/USAGE.md`'s panel keyboard table (one row per panel: what
Enter, `x`, Left/Right and Tab do there).
Commit: `docs(panels): keyboard table and rig coverage`.
