# M43: the launcher as a command palette

**Date:** 2026-08-25
**Status:** approved, pre-implementation
**Spec:** `docs/superpowers/specs/2026-08-25-shadcn-omarchy-redesign.md`
("Launcher", "Type", "Depth", "Keyboard model"); `docs/DESIGN.md` §3
"Launcher". Spec wins on conflict.
**Builds on:** M41 primitives, M42's panel ports (same D1 recipe).

## Why

`shell/Surfaces/Menu/Menu.qml` (2311 lines), `MenuRow.qml`,
`MenuActionBar.qml`, the picker grid, the split clipboard route, the app
views and `TrayMenu.qml` still draw the ledger: inverted cursor row,
uppercase breadcrumb band, shared rules, mono everywhere. The launcher is the
front door of the whole shell and the one surface every keybind lands on.

## Scope

In: `Menu.qml`, `MenuRow.qml`, `MenuActionBar.qml`, `views/*.qml`
(`MonitorView` and any sibling), the picker grid mode, the split route, the
`select`/`input` IPC modes, `TrayMenu.qml`, rig legs for all of them on
`dev/smoke.sh`, docs. Out: menu data (`shell/Menu/*.js`, routes, providers,
search) beyond what the chrome needs; new routes; M46's screenshots.

## Locked decisions

- D1: same exit checks as M42 D1 on every file touched (no raw glyph, no
  `MetaLabel`, no dither, no `Theme.fontFamily`, no mapped Cell prop, no
  literal size or colour, no em dash in strings).
- D2: the launcher is shadcn's Command. `Card` `radiusXl` `popupWidthMenu`
  wide, top edge at 30% of the output height, over the existing 0.5 black
  scrim; input row is a `search` `Icon` plus a `TextInput` in sans with a
  1px `border` rule below it and no other frame; breadcrumb as `secondary`
  chips (`Cell` `radiusSm`, sans, sentence case) above the list, hidden at
  root; rows are `Cell`s with `radius: 0` and no border inside the card
  (the list is one column, `rowGap` 0, the cursor row painted `accent` with
  `accentForeground`, hover the same fill, no ring in the list); row layout
  is `Icon` (or app icon image), label sans `medium`, detail sans
  `mutedForeground`, trailing keybind chord or count in mono; footer is one
  `caption` `mutedForeground` line `↑↓ move  ↵ open  esc back` (sentence
  case, sans, the arrows are text). Section headers inside a route (`APPS`,
  `RECENT`) are `SectionLabel`s.
- D3: the picker grid keeps its layout; cells get `radiusMd` thumbnails
  with a 1px `border`, the cursor is the ring, the `Dark | Light` switcher
  is a segmented control built from two `Cell`s in a `muted` group (a
  `Segmented` primitive is M44's if two surfaces need it; here it is local).
- D4: split routes (clipboard, share history) keep the left list / right
  preview shape; the preview is a `Card` `radiusMd` inner card. App views
  (`MonitorView`) use the M42 monitor panel's rows as their vocabulary.
- D5: `select` and `input` IPC modes render as the same palette with the
  prompt as the input placeholder; nothing about their answer-channel files
  changes.
- D6: `TrayMenu.qml` is a `popover` `Card` `radiusMd` with rows like the
  launcher's, checkmarks as `check` icons, submenus with `chevron-right`.
