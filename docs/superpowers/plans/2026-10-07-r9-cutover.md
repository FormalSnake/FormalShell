# R9: cutover

Goal: the Rust shell is FormalShell. One package, one greeter, no
Quickshell, no QML, both Linux hosts running it.

Gate (checked 2026-10-07): `2026-10-07-r9-final-sweep.md` shows every leg
passing under `FS_IMPL=rust`, the QML table unchanged from before the
rewrite, and the parity backlog empty or each remaining line accepted by the
owner.

## Task 1: packaging

- `.#formalshell` builds the Rust binary (today `.#formalshell-rs`); the
  old QML package and `.#formalshell-rs` go. `formalshell-ipc` is the IPC
  entry point everywhere (Hyprland Lua binds, docs, the home-manager
  module).
- `nixos-module.nix` and the home-manager module start the Rust binary;
  `services.formalshell-greeter.implementation` goes, the Rust greeter is
  the greeter.
- No native distro packages (owner, 2026-10-07): `packaging/`,
  `dev/native-check.sh`, `dev/smoke.d/native.sh` and the release
  workflow's package uploads go. In their place the spec's "Installing"
  section: the release tarball built in CI, `install.sh` with its one
  package-name table for pacman, apt and dnf, and the `formalshell
  install|update|uninstall` subcommands. Tested in three fresh containers
  (Arch, Debian, Fedora) from nothing to a running shell in a nested
  session; no other distros.

## Task 2: delete the QML shell

- `shell/`, `greeter/`'s QML, `tests/*.qml` and their stubs and fixtures
  that only QML read, the quickshell flake input, the `qml-tests` and
  `qmllint` checks, `*.frag` shaders, `FS_IMPL` (Rust is the only
  implementation; `dev/smoke.sh` loses its QML path), `dev/parity.sh` and
  `dev/ipc-golden.sh`'s recording against `qs` (the golden file stays as a
  fixed contract).
- Pure logic crates keep their ported tests; fixtures they read move under
  `crates/`.

## Task 3: docs

- CLAUDE.md rewritten for the Rust tree (verification loop, rig, hard
  rules: the pure QML/JS rule is gone; the ScreencopyView ban becomes the
  capture rule), README, docs/USAGE.md, docs/ARCHITECTURE.md, DESIGN.md
  references to QML components.

## Task 4: measure on e1504g (owner present)

- The R0 table again with the real shell, nested on e1504g in power
  saver: idle CPU, spinner CPU, panel and launcher frame times, the 33 ms
  bar gap during a launcher open, RSS after an hour, cold start. Against
  the spec's budgets.

`--r0-measure 600` for each shell. Power profile `power-saver` for all
three runs (set with `sudo -n`: polkit refuses `powerprofilesctl set` over

### Rerun on g815, throttled (owner, 2026-10-07: e1504g is gone)

Same table, nested on g815, with both shells' process trees pinned to two

### Results, g815 throttled, 2026-10-07

Rust is the shipped `.#formalshell` at 4df6c75d on the repo lock. QML is
`nix/qml-package.nix` at the same commit, built against g815's own nixpkgs
(`55ba7f49`): on the repo lock its glibc 2.42 cannot load the host's mesa.
Each shell ran under `taskset -c 16,17` with E-cores 16-19 capped at
`scaling_max_freq` 1800000, which reads 1.7 GHz under load. The whole
module is capped because 16-19 share one clock: with only 16-17 capped
they ran at up to 4.4 GHz whenever 18 or 19 was busy. A trap put 4700000
back after every run, checked after the last. Load was under 4 at each
start, and every run took the NativeDesktop bench's rig lock
(`/tmp/nd-g815-rig.lock`).

The nested window was not on the owner's screen. g815's live session
composites on the NVIDIA card (its dmabuf main device is renderD129), and
aquamarine 0.15 renders on whatever device the parent names, so a nested
window on screen can only render on NVIDIA. The runs used NativeDesktop's
rig shape instead: a headless mutter 50.4 parent on Mesa, so the nested
Hyprland 0.56.2 renders on renderD128 (`Mesa Intel(R) Graphics (ARL)` in
its log), drawing a Hyprland headless output at 1920x1080@60. Frame
callbacks came every 16 to 17 ms in every run.

- Rust rows with two values are `--r0-measure 600` then `--r0-measure
  3600`. The launcher rows are three `--menu-budget` runs.
- Idle: one bar commit (the clock's minute) and no frame callback
  requested in the window, yet 0.18 s and 0.24 s of CPU. No cause yet,
  as on e1504g.
- Panel frames: Rust's worst frame is render, copy and react together on
  the panel surface, with commits 16 to 19 ms apart. QML's worst is the
  render thread's `frame rendered in` and the GUI thread's prepare, with
  frames up to 88 ms apart.
- Launcher: the first commit is mostly the compositor's configure (5 to
  10 ms), with 1 to 2 ms of the shell's own. The 33 ms gap budget is
  two frames; the bar missed none.
- RSS: 117 MB until the nested screensaver started at 532 s. From there
  it drew at 60 fps to the end of every run: 149 MB at 600 s, then 165 MB
  from 20 minutes on.
- Every Rust run left an `omarchy-iphone-bridge listen` child alive after
  the session's cgroup teardown, reparented to pid 1 in the root cgroup.
  The first one held the rig lock's fd and stalled both benches for 20
  minutes. Each was killed after its run.
- Two QML threads were seen on cpus 3 and 5, so its pin did not hold for
  the whole process.
- After round 4 (d5c7a57c, Rust only, the same rig): `--menu-budget`
  once, then `--r0-measure 600` and `--r0-measure 3600`. Each sent one
  `screensaver stop` 4 s before the RSS sample, so the screensaver ran
  from 532 s to the stop and the second figure is after it let go. The
  idle window again held one clock commit and no frame request. The
  shell's children (three `wl-paste --watch`, the herdr poll and
  `omarchy-iphone-bridge`) ended with it in every run: the rig's orphan
  check passed and nothing was left to kill.
- Idle attribution at d5c7a57c, same rig: the r0 idle minute read 21
  ticks. During that minute the per-thread deltas, `busctl monitor` on
  both buses and a 60 s `perf record -g` all named one waker: BlueZ.
  - BlueZ signals: 695 `PropertiesChanged` on `/org/bluez/hci0/dev_*`
    (RSSI from a discovery the shell did not start), plus 27
    `InterfacesAdded`/`InterfacesRemoved`, all on the system bus.
  - Those signals cost the most of any waker. The system-bus zbus thread
    took 679 wakeups and 5 ticks receiving them (29% of samples). On
    `fs-service` (779 wakeups, 11 ticks, 51%), each one goes through
    `fs_bluez::client::handle_signal`, then
    `services::devices::bluetooth::snapshot`, which clones the whole
    `Bluez::state` map and rebuilds `devices_of`, `headsets::read` and
    `earbuds_devices`.
  - Each snapshot is posted to the UI loop: the main thread took 469
    wakeups and 3 ticks (12%) in `App::receive` and `Store::apply`,
    dropping the old `Bluetooth` value with nothing on screen to commit.
    The `async-io` reactor took 1456 wakeups and 1 tick (8%).
  - Everything else is small. The herdr poll child's pipe woke
    `fs-service` about 146 times a minute and pipewire about once a
    second (1%). UPower sent 4 `PropertiesChanged`, answered with 4
    `GetAll` calls. The clock made one commit. Nothing was captured on
    the nested session bus.
- After round 5 (43e163a9, Rust only, the same rig, 2026-10-08 01:40 to
