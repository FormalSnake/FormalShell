# M75: iPhone integration

Owner ask (2026-09-28): integrate the shell with the owner's iPhone. iPhone
notifications, iPhone battery, LocalSend and AirPlay, each wired into the
panels and routes that already exist rather than standing alone. iPhone
notifications follow the phone's Focus where that is knowable, and a message
that the owner's Linux iMessage client (`~/Developer/messages`, app id
`es.canarycoders.messages`, app name `Messages`) already raised must not
arrive twice. Everything configurable. KDE Connect is out (owner).

Work happens on branch `feat/iphone` in `../FormalShell-iphone`; main is
being edited by another session (M74 spaces), rebase before merge.

## Upstream facts this leans on (checked 2026-09-28)

- ancs4linux (github.com/pzmarzly/ancs4linux @ b658546, GPL, not in
  nixpkgs; Python >=3.10, hatchling, deps dasbus, PyGObject, typer). System
  bus, object `/`. `ancs4linux.Observer`: signals `ShowNotification(s
  json)`, `DismissNotification(u id)`, method `InvokeDeviceAction(s
  device_handle, u id, b positive)`. `ancs4linux.Advertising`:
  `GetAllHci`, `EnableAdvertising(hci, name)`, `EnablePairing`,
  `DisablePairing`, signal `PairingCode(s)`. Units in `autorun/`
  (observer and advertising are system `Type=dbus` units; D-Bus policy lets
  the `ancs4linux` group talk to them).
- Upstream JSON carries `device_name, device_handle, app_id, app_name, id,
  title, body, positive_action, negative_action`. The metadata patch in
  kbbahaPro/omarchy-iphone @ 586f37d (MIT, `patches/ancs4linux-metadata.patch`)
  adds `subtitle, date, category_id, silent, important, preexisting,
  session`, and dismiss sync. Apply it.
- omarchy-iphone (MIT, a Quickshell plugin for Omarchy) is prior art for the
  whole feature: `bin/omarchy-iphone-bridge` turns the system-bus signals
  into JSONL on stdout (`listen`, `invoke`, `pair`, `hci`), `bin/omarchy-iphone-ams`
  is an Apple Media Service GATT client (`listen` JSONL now-playing,
  `command play|pause|toggle|next|prev|volup|voldown`). Package both
  scripts as runtime CLIs; any QML substantially ported from it carries
  `// Portions from omarchy-iphone (MIT, Copyright 2026 kbbahaPro)`.
- Focus: iOS still sends Focus-intercepted notifications over ANCS with
  `EventFlagSilent` set, honouring the Focus allow-list (PebbleOS PR #1772,
  tested on a device). No BLE accessory can read the Focus state itself.
  So `silent` is the Focus signal, and "phone is in Focus" is only ever a
  heuristic over recent `silent` arrivals.
- iPhone battery: Quickshell `BluetoothDevice.battery` is 0..1 behind
  `batteryAvailable` (`src/bluetooth/device.hpp:98`), fed by
  `org.bluez.Battery1`. Whether the phone exposes GATT 0x180F over the ANCS
  bond is unverified: show it when BlueZ has it, otherwise no battery row.
- LocalSend: official `localsend-cli` (Rust, `cli/` in localsend/localsend)
  has headless `send --to <alias|ip> <paths>` only on `main`; the TUI is
  the only receiver. 0w0mewo/localsend-cli (Go) has `scan`, `send -f -p`,
  `recv -n -d`. Task 5 picks one after running both; the shell needs peer
  discovery, file send, text send and unattended receive into a dir.
- UxPlay (nixpkgs 1.73.7): `-n name -nh`, `-vs 0` no video window, `-md
  file` metadata text (removed on exit), `-ca file` cover art JPEG, `-dacp
  file` exists only while a client is connected. No MPRIS.

## Settings (read-only settings.json, documented in `Config.qml`'s header)

- `iphone.enable` (true): off stops every bridge child.
- `iphone.notifications.enable` (true).
- `iphone.notifications.focus` (`"respect"`): `respect` routes a `silent`
  notification to the centre's history with no toast and no sound;
  `hide` drops it; `ignore` treats it like any other.
- `iphone.notifications.syncDnd` (false): while the heuristic says the
  phone is in Focus (a `silent` arrival in the last `focusWindow` seconds,
  default 900, and no non-silent one since), the shell's DND is on; it
  never turns off a DND the owner set by hand.
- `iphone.notifications.dedupe` (default below): a list of
  `{ phone: <bundle id>, local: [<appName or desktopEntry>...], window:
  <seconds> }`. Two notifications match when their normalised title
  (sender) and body agree inside `window`. The local one wins: a phone
  arrival matching a live local one is dropped; a local arrival matching a
  phone one replaces it (the phone card is removed, not left as a second).
  Default `[{ "phone": "com.apple.MobileSMS", "local": ["Messages",
  "es.canarycoders.messages"], "window": 30 }]`. `[]` disables it.
- `iphone.notifications.block` ([]): bundle ids never mirrored.
- `iphone.copyCodes` (false): a one-time code in a mirrored notification
  goes to the clipboard.
- `airplay.enable` (false): the shell owns a `uxplay` child.
  `airplay.name` (hostname).
- `localsend.receive` (false): the shell owns a receiver child.
  `localsend.alias` (hostname), `localsend.dir` (`~/Downloads`).

Styling of every new surface is the theme's (`specs/2026-09-18-theme-boundary.md`),
never a key.

## Task 5: LocalSend (sonnet)

- CLI decision (Task 1, read both at HEAD on 2026-09-28): 0w0mewo/localsend-cli
  (Go, MIT, `github.com/0w0mewo/localsend-cli` rev `7865fb1cf26e4f782c6400167a7d218d69313cff`,
  packaged at `nix/localsend-cli.nix`, binary `localsend-cli`). The official
  localsend/localsend `cli/` crate (Rust) on `main` only has `send --to
  <alias|ip> <paths>...`: headless mode discovers the destination, sends,
  and exits; it declines every incoming `PrepareUpload` (`cli/src/app/headless.rs`
  `handle_server_event`, `PrepareUploadDecisionV2::Decline`), and has no
  `recv`/`scan` at all, so unattended receive and scriptable discovery are
  not there to pick. 0w0mewo's Go CLI has all three verbs LocalsendService
  needs:
  - `localsend-cli scan -t <seconds>` (default 4s): listens for peer
    announcements, then prints to stdout either `No device found` (to
    stderr, actually: `scan.go` writes the empty case to `os.Stderr`) or
    `Found Devices: \n\tName: <alias>, Version: <ver>, Address: <ip>:<port>, Protocol: <proto>\n`
    once per peer, one peer per line under that header. Parse with a
    `^\tName: (.*), Version: (.*), Address: (.*):(\d+), Protocol: (.*)$`
    line match; no JSON mode exists.
  - `localsend-cli send --ip <ip> -f <path> [-p <pin>] [--https=false]`:
    `-f/--file` repeats for multiple paths (file or directory, recurses).
    No `--to <alias>`, only `--ip`, so LocalsendService resolves an alias to
    an IP itself off its last `scan`. No text-send flag either: send a
    clipboard text row by writing it to a temp `.txt` and sending that as a
    file, same as the official CLI would need. Progress and errors go to
    stderr as structured `slog` lines (`level=INFO msg="Start sending"
    file=...`, `level=INFO msg=Done`, `level=ERROR msg="Fail to send"
    error=...`); the exit code is 0 even on a per-file failure logged
    through `slog.Error` inside the loop (only `sender.Start()`'s own
    top-level error is fatal), so LocalsendService has to watch stderr for
    `level=ERROR`, not just the exit code.
  - `localsend-cli recv -n <alias> -d <dir> [-p <pin>] [--https=false]`:
    binds `:53317`, advertises, and auto-accepts every `PreUploadReq` with
    no confirmation (`internal/localsend/recv/handlers.go`
    `preUploadHandler` only checks the PIN, never prompts) before saving
    into `<dir>`, which is what "unattended receive" requires. Runs until
    SIGTERM/SIGINT (`utils.WaitForSignal()`); logs each accept as `level=INFO
    msg="Accepting file" remote=<ip> session=<id>` on stderr, and each saved
    file only implicitly (no per-file "saved" log line), so
    LocalsendService should watch the destination directory (inotify or a
    poll) for the toast's Open/Show-in-folder actions rather than parsing a
    "done" line out of the log.
  - Risk carried forward from Task 1: upstream's own README calls the
    project deprecated and only guaranteed against the official app's
    v1.17.0 (current is v1.18.0), though it claims the same LocalSend v2
    wire protocol. `dev/smoke.d/localsend.sh`'s real loopback transfer
    (Task 7) is what actually re-checks this against a second CLI instance;
    if it breaks, the fallback in Task 5 below (the old `localsend_app`
    spawn) is what a broken CLI degrades to.
- `LocalsendService`: receiver child behind
  `localsend.receive`, a toast per received file with Open and Show in
  folder actions, `peers` from discovery.
- Launcher: the `share` route lists discovered peers under Send, text from
  the clipboard row and files from the clipboard's image rows; the capture
  SAVED notification gains a Send to phone action; `localsend` IPC target
  (`peers`, `send <peer> <path>`, `status`). The old `localsend_app`
  spawn stays as the fallback Receive row when no CLI is on PATH.
