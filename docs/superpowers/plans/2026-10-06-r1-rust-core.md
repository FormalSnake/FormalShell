# R1: Rust core

Goal: everything every later surface stands on. Config, state, themes and
palette, the IPC contract, the Hyprland backend and the thread model from
`specs/2026-10-06-rust-rewrite.md`, with the first legs passing under
`FS_IMPL=rust`.

Facts this plan rests on (checked 2026-10-06):

- R0 is done (`ab25b4e`): `crates/formalshell-rs` (~2.5k lines) has the
  scene, damage, vello_cpu render, parley text with fontconfig hinting,
  motion (Presence, Joint, Deform, Shoulders), a bar strip and a spike
  panel, controlled over an ad hoc `ctl` socket.
- The QML sources this ports: `shell/Core/Config.qml` (501 lines),
  `shell/Core/State.qml`, `shell/Core/Theme.qml`, `shell/Theme/` (tokens,
  style, themes/*.js, matugen, flexoki, zenbones, sun, barpaint,
  ThemeEngine), `shell/Ipc/*.qml`, `shell/Compositor/BackendBase.qml` and
  `shell/Compositor/hyprland/HyprlandBackend.qml`.
- Smoke legs call IPC as `"$qs_bin" ipc -p "$shell_path" call <target>
  <fn> [args]` (640 calls across `dev/smoke.d/`).

Tasks 2, 3 and 4 depend only on Task 1 and run in parallel worktrees.
Task 5 needs all of them.

## Task 1: runtime skeleton

- The thread model from the spec: the UI `calloop` loop, one service
  thread with a single-threaded async executor, a blocking pool of at most
  two threads that exits when idle. Services publish state diffs over a
  channel the UI loop drains; nothing on the UI loop awaits.
- A typed state store the UI reads and services write through diffs, so
  later milestones add a service by adding a module, not by touching the
  loop.
- The R0 `ctl` socket goes; the real IPC server (Task 4) replaces it.
- Verify: the R0 bar and panel still behave as in R0 under `FS_IMPL=rust`
  in the VM, idle CPU still 0, and a test proving a blocking job never
  delays a UI frame.

## Task 2: config and state

- `settings.json` read only, every key and default `Core/Config.qml`
  resolves, its warnings worded the same. A symlink retarget (what
  home-manager does) is seen, as `--config-reload` proves.
- `state.json` under `$XDG_STATE_HOME/formalshell/`, same shape, written
  atomically from the service thread.
- Rust tests port `tests/tst_config*.qml` and `tests/tst_state*.qml`.

## Task 3: themes and palette

- `shell/Theme/themes/*.js` become `themes/*.json` with the same keys,
  read by the QML shell too (it is still the shipped shell), so there is
  one source. `Theme.box()`, tokens and style resolve identically in Rust.
- Matugen orchestration, Flexoki and Zenbones palettes, the sun schedule,
  bar paint, light/dark and auto mode, matching `ThemeEngine.qml`. Child
  processes run on the service thread.
- Rust tests port the theme tests, including "every role in every table".

## Task 4: IPC

- A Unix socket server under `$XDG_RUNTIME_DIR/formalshell/` and a
  `formalshell-ipc call <target> <fn> [args...]` client binary. Output is
  byte-identical to `qs ipc call`, including its argument splitting and
  error strings, read off the built `qs` and the existing handlers.
- A registry where each target is one module. R1 ports `debug`, `theme`,
  `bar` (the verbs R2 does not need beyond the strip), and the unknown
  target and unknown function errors.
- `dev/smoke.sh` and every leg reach the shell through one `$ipc`
  command, so `FS_IMPL=rust` swaps it in one place.

## Task 5: Hyprland backend and legs

- The full `BackendBase.qml` contract on raw sockets: windows,
  workspaces, monitors, fullscreen coverage, events, writes through
  `hyprctl eval` with `address:0x...` selectors built at the wire boundary
  only. Ids stay opaque strings.
- The R0 bar reads workspaces through it.
- Legs passing under `FS_IMPL=rust` in the VM: `--dump`,
  `--config-reload`, `--theme-toggle`, `--theme-auto`, `--flexoki`,
  `--workspaces`.
